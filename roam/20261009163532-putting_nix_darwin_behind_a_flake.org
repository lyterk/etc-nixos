Your =flake.nix= needs =nix-darwin= as an input, a =darwinSystem= builder, and the =mac-lyterk= host added. The =home.nix= has Linux-specific packages/services that won't build on Darwin — you'll need to split that or guard it.

*Issues I see:*
- =home.nix= references Linux-only packages (=gtklock=, =blueman=, =bluez=, =kanshi=, =wob=, =wev=, =pamixer=, =pulseaudio=, =mako=, =swayidle=, =sway=, =waybar=, =rofi-wayland=, =grim=, =slurp=, =wl-clipboard=, =xorg.xhost=, =captive-browser=, =gparted=, =parted=). These won't build on Darwin.
- =configuration.nix= uses =nix-darwin= options (=homebrew=, =security.pam.services.sudo_local=, =system.defaults=, =system.primaryUser=) but your flake doesn't have =nix-darwin= at all.
- =system.primaryUser= and =homebrew= are nix-darwin-specific — they're already correct in =configuration.nix=, just missing from the flake.

*Also recommended:*
- Split =home.nix= into a =common.nix= + =linux.nix= + =darwin.nix=, or use =pkgs.stdenv.isLinux= guards around Linux-only packages/services. The sway/wayland config is ~200 lines that simply won't apply on macOS.
- =mac-lyterk= doesn't need =hardware.nix= — nix-darwin has no hardware module concept, so I omitted it above.
- Consider whether =aarch64-darwin= or =x86_64-darwin= is correct for your Mac. Apple Silicon = =aarch64-darwin=.

A few notes:

1. *SSH/GPG keys themselves* must be physically copied (e.g. =scp ~/.ssh/id_ed25519 mac:.ssh/=) — Nix manages /config/, not key material. Consider using =sops-nix= on the mac if you want to manage secrets declaratively.

2. *=pinentry-mac=* is already in your homebrew brews — on macOS =services.gpg-agent= is supported by home-manager but uses launchd instead of systemd.

3. *Firefox*: You'll need to check whether your =shared/firefox= module uses any Linux-only options (like =stylix= targets) — you may need to guard those with =pkgs.stdenv.isDarwin=.

4. *=atuin=* needs to be added to =mac-lyterk/configuration.nix= system packages or home packages if you want shell history sync.
