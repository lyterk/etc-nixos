A few things to check:

1. *=tomat= not in PATH* – Waybar runs in a systemd service environment which may not have your user PATH. Try using the full path to the =tomat= binary, e.g.:
   #+begin_src diff
   - exec = "tomat status";
   + exec = "${pkgs.tomat}/bin/tomat status";
   #+end_src
   (assuming =tomat= is a nix package)

2. *=return-type = "json"= mismatch* – If =tomat status= doesn't actually output JSON, waybar will silently drop it. Either:
   - Remove =return-type = "json";= if it outputs plain text, or
   - Ensure =tomat status= outputs valid JSON like ={"text": "25:00", "tooltip": "work"}=

3. *=format= with ={icon}=* – Since there's no =format-icons= defined for =custom/tomat=, ={icon}= will be empty. Simplify to:
   #+begin_src diff
   - format = "{icon} 🍅";
   + format = "{} 🍅";
   #+end_src

4. *Waybar not restarted* – After a config change, make sure to restart the waybar systemd service:
   #+begin_src 
   systemctl --user restart waybar
   #+end_src

Most likely culprit is *#2* (JSON format mismatch) or *#1* (PATH issue).
